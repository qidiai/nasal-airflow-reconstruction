## 2. 后端抽象（`code/pipeline/solver_backend.py`）

- `backend = auto | custom | openfoam`，默认 **auto**：
  `flowscope[.exe]` 存在 → custom；否则 openfoam。
- custom 调用：`flowscope run <caseDir> --max-iter 1500 --write-every 500
  --p-reltol 1e-3 --out <outDir>`（对齐 `numerical-contract.md` 与 M2 对拍口径）。
- 结果目录适配（保持 downstream 行为不变）：
  - `fields_<iter>.vtk` → `VTK/<case>_<iter>/internal.vtu`（hexahedron + cell U/p，
    供 step5 `meshio.read`）；
  - §11 stdout 指标 → `后处理/metrics.json`（patches/totals/wss 三段）+
    `后处理/solver-contract.txt`（原始指标段留证）。
- WSS：优先复用 M2 `round6_extract.wss_stats`（真实法向距离），失败回退日志
  mean/max 并如实披露 p95=NaN。

### Run-B 路由（已知边界，硬约束）

- Run-A：custom 优先（L1 pA +1.61% / pB −0.63%，±2% 内）。
- Run-B：`cells <= 50,000` → custom；`> 50,000` → openfoam（若可用）。
  **实现口径（收尾核对）**：流水线不自动发起 Run-B 求解（沿用交接/手工流程）；
  `solver_backend.choose_run_b_backend()` 提供判定，`run_all` 将其写入
  manifest `stages.S5_solve.run_b_routing` 作为披露。根 README 已按此表述。
- **已知失稳**：custom Run-B 在 pA 满分辨率（269,913 cells）发散——鼻阀高
  Péclet 速度峰经 HbyA→压力→速度指数放大，六种方案均不能阻止
  （`solver/docs/equivalence-report.md` §2.2、conditions-ledger G-C3b）。
  **因此 OpenFOAM 后端保留不删**，作为 Run-B 大网格与 L3 回归的对拍真值源。
- 默认行为已写入 `legacy/openfoam-reference/README.md` 与根 `NOTICE`。
